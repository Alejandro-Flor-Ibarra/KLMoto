# Sesión — 2026-11-26

## Hechos confirmados

- KLMoto es una aplicación Android nativa implementada con Kotlin, layouts XML, Material 3 y `ConstraintLayout`.
- La pantalla principal contiene un encabezado, un panel de kilometraje con botón de viaje, un bloque de registro automático con `SwitchMaterial` y una navegación inferior.
- La barra inferior utiliza `BottomNavigationView` y carga sus opciones desde `res/menu/bottom_navigation_menu.xml`.
- Los iconos SVG requieren conversión a Vector Drawable XML para usarse en recursos Android. La tintura de iconos de la barra se configuró como nula para permitir mostrar los colores definidos en vectores multicolor.
- `MainActivity` configura el layout y los insets. No se encontró lógica de selección para navegar a otras pantallas ni funcionalidad de registro GPS.
- El proyecto se configuró para compilar y apuntar a API 37 tras el aviso de compatibilidad de `androidx.core:1.19.1`.
- La pantalla de cuidados mostrará una tabla de mantenimientos pendientes, con ejemplos como cambio de discos de clutch, cambio de pastillas de freno y lubricación de guayas.
- Un agente de IA buscará y analizará el manual de taller correspondiente a la moto para recomendar mantenimientos según sus indicaciones.
- Si no se encuentra el manual correcto, la app ofrecerá alternativas: solicitar una foto del manual o presentar recomendaciones genéricas claramente marcadas como orientativas.
- La consulta de talleres se hará mediante una API de Google Maps. Se listarán los talleres encontrados con distancia y calificación, y el usuario podrá ajustar el peso de ambos criterios en el orden.
- La actividad inicial pedirá el nombre del usuario y los datos de la moto. Para identificarla, se podrá elegir entre un catálogo de motos o aportar una foto del manual.
- Para buscar un manual desde el catálogo se solicitarán marca, modelo, año, cilindrada y versión exacta de la moto.

## Decisiones confirmadas

- La selección inicial de moto ofrecerá dos posibilidades: catálogo de motos o foto del manual.
- El catálogo de motos solicitará marca, modelo, año, cilindrada y versión exacta.
- Los talleres encontrados se ordenarán combinando distancia y calificación, con pesos ajustables por el usuario.
- Si no se identifica un manual correcto, se ofrecerá la opción de cargar una foto y la alternativa de recomendaciones genéricas orientativas.

## Pendientes

- Definir fuentes y validación del manual que consultará el agente de IA.
- Definir cómo el usuario confirma que la IA identificó correctamente la moto y el manual.
- Definir cómo se ajustarán en la interfaz los pesos de distancia y calificación.
- Confirmar si las dos alternativas ante la falta de manual se presentan juntas o como opciones excluyentes.
- Definir si una cuenta podrá administrar varias motos.
- Definir el alcance del GPS y los permisos de ubicación.
- Conectar la navegación inferior con las pantallas Inicio, Cuidados y Talleres.

## Riesgos o contradicciones

- El texto informativo de ubicación menciona acceso permanente, mientras que la intención exacta de registro y permisos aún no está definida.
- La interfaz muestra controles de iniciar viaje, registro automático y pausa, pero su comportamiento todavía no está implementado.
- Los SVG no se pueden referenciar directamente como `@drawable`; cada icono debe convertirse a Vector Drawable y su archivo resultante conservar los colores y dimensiones adecuados.
- La búsqueda y análisis automatizados de manuales dependen de identificar correctamente marca, modelo, año y variante; falta definir fuentes y verificación para evitar recomendaciones basadas en un manual equivocado.
